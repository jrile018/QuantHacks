# Team source contract

Keep each new source on its own branch in this repository. Start by committing a small, reviewable source manifest and source URLs; storage and bulk collection of the underlying data are deferred. Put the source's batch manifest at `configs/sources/<source_id>/manifest.jsonl` and keep downloaded documents locally under ignored `data/raw/team_sources/<source_id>/` (`data/raw/` is ignored by Git). A `source_path` from that manifest to a local file starts with `../../../data/raw/team_sources/<source_id>/`. Use a stable source ID and unique, stable document IDs so two sources cannot accidentally share an identity.

## Runnable batch input

[`scripts/run_document_batch.py`](../../scripts/run_document_batch.py) reads **JSON Lines**, one JSON object per line. Each row needs a nonempty string `document_id` and a nonempty string `source_path`. A relative path is resolved from the manifest's directory, not the shell's working directory. An optional `source_sha256` is checked against the local file's bytes; include it only when the bytes and hash are known. Duplicate document IDs and empty manifests fail validation. A source URL can be recorded as extra provenance metadata, but a URL is **not** a runnable `source_path`: the batch runner opens local files and does not fetch URLs. The runner preserves extra input fields in its journal's `input_record`; it does not interpret their meaning or turn them into verified publication times or source identities.

For example, after a document has been obtained locally:

```jsonl
{"document_id":"example_source:release-001","source_path":"../../../data/raw/team_sources/example_source/release-001.pdf","source_url":"https://example.org/release-001.pdf"}
```

The batch supports native text/HTML, native PDF text, and explicit PDF/image OCR with Tesseract or GLM. Select an OCR engine explicitly where needed. Native PDF extraction rejects sparse pages (fewer than 40 alphanumeric characters) that need the explicit OCR route. The --force-ocr flag recognizes every page but can retain embedded text alongside recognized text. Do not put a saved OCR JSON file in this batch manifest: the batch hashes the JSON file as its input, while the transcript adapter checks the OCR payload's `source_sha256` against the original document bytes. Those are different hashes. The SEC accession analyzer has a separate `--ocr-map` import route for saved OCR JSON; it requires the OCR payload's original-document hash to match its inventoried source. Outputs are a checkpoint journal, raw OCR artifacts when applicable, and normalized transcript JSON. The runner hashes each local input and output, checks supplied hashes, and records batch/adapter/config revisions. See [`src/document_transcript.py`](../../src/document_transcript.py) for the actual transcript fields and extraction behavior.

## Shared output, source-specific identity

Reuse the implemented transcript and evidence contracts. A normalized transcript carries `document_id`, `source_sha256`, `text_sha256`, `normalized_text`, `normalization_version`, `extraction_method`, `engine_revision`, `adapter_revision`, `settings`, page/table records, quality flags, and `processing_completed_at_utc`. Evidence refers to that exact transcript by document and text hash, with zero-based `char_start` and exclusive `char_end`; its `quoted_text` must equal the corresponding normalized-text slice. Keep original bytes/OCR artifacts, source hashes, page boundaries, quality flags, and adapter/provider versions so another agent can reproduce or audit a quotation. See [`src/document_evidence.py`](../../src/document_evidence.py) for the implemented evidence contract.

The SEC inventory in [`src/document_manifest.py`](../../src/document_manifest.py) is a **richer, SEC-specific** layer: CIK, accession, form, SEC items, filing/exhibit roles, amendment/event linkage, SEC archive URL status, source hash, receipt, acceptance and supported public-availability evidence. It is not the generic JSONL batch input. An adapter for a non-SEC source may produce the shared transcript/evidence shape and retain that source's real identifiers, URLs, timestamps and provenance in source-specific records. It must not invent CIK, accession, SEC item, filing role or acceptance time to fit the SEC inventory.

Keep distinct clocks distinct. Record a known time as an exact UTC instant with its supporting evidence; leave an unknown time null or explicitly unavailable. A download receipt or processing completion is not proof of first public availability. Preserve the original publisher identity and URL status, including whether a URL was merely supplied or its bytes were actually checked. Source-specific metadata in a batch row is just recorded input until an adapter validates and uses it. If the same URL yields different bytes, retain both hashes as separate source versions and flag the conflict for review. Quarantine must carry through dependent records; a normalized-text match cannot silently clear a raw-source conflict.

Successful extraction or OCR means text was processed. It does not establish semantic accuracy, historical availability, issuer/security mapping, market-data coverage, a valid feature, or eligibility for a financial backtest.

Add source-specific adapters and tests on the source branch as needed. Propose changes to shared schemas in a separate PR, routed to the affected owner and consumers with migration impact and acceptance evidence. This source guide defines no market feature or target schema. Benchmark owns the financial producer, the industry work owns dated industry/history and source quarantine, and Post Benchmark owns canonical decision records, FeaturePanel/registry, evaluator, and consumer acceptance. A source manifest or transcript does not bypass those owners' acceptance checks.

Further owner-workstream references, when published or available in their checkouts, are `docs/8k-document-analysis.md`, `docs/superpowers/specs/2026-10-03-8k-document-analysis-design.md`, `docs/coordination/architecture-contract.md`, and `docs/coordination/feature-matrix-integration.md`. These guides are not required to use this first-push source contract; the linked code above defines the implemented document schemas.
